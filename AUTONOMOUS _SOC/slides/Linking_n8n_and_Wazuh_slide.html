Autonomous Cloud SOC

Linking n8n and Wazuh

Two tools, talking to each other automatically: Wazuh watches the honeypot, n8n decides what to do, and calls back to block the attacker.

Windows Honeypot

Attacker tries repeated logins (RDP brute-force)

Wazuh

Watches the logs and raises an alert

n8n

Reads the alert, decides, and acts

Blocked & Logged

IP blocked, incident recorded automatically

n8n and Wazuh run in separate Docker containers, so they talk over host.docker.internal — never "localhost"

Two logins, one workflow

n8n stores a Wazuh Indexer login (port 9200, for reading alerts) and a Wazuh Manager login (port 55000, for taking action).

Real action, not just a message

n8n calls Wazuh's Active Response API directly — it tells Wazuh to block the IP, it doesn't just notify someone.

Seconds, not minutes

Detection to blocked IP happens automatically — no analyst has to click anything.
