How n8n and Wazuh Are Linked

Five steps connect Wazuh's alerts to n8n's automated response — from the network bridge to a tested, working block.

1

Bridge the Containers

n8n and Wazuh run in separate Docker containers, so the connection uses host.docker.internal instead of localhost.

2

Sign In to Wazuh

Two separate logins are needed: the Indexer API (port 9200) for reading alerts, and the Manager API (port 55000) for taking action.

3

Save Credentials in n8n

Both logins are stored as secure, reusable credentials inside n8n — entered once, then used wherever they're needed.

4

Wire Credentials to the Workflow

Each step in the n8n workflow is connected to the right credential: one to read Wazuh's alerts, one to send a response back.

5

Test Before Going Live

A trial run confirms n8n can read a real Wazuh alert and trigger an actual block — proven safe before the workflow runs unattended.
