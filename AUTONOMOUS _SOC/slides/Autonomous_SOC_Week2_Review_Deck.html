Autonomous Cloud SOC · Setup Walkthrough

How n8n and Wazuh Are Linked

Five steps connect Wazuh's alerts to n8n's automated response — from the network bridge to a tested, working block.

1

Bridge the Containers

n8n and Wazuh run in separate Docker containers, so the connection uses host.docker.internal instead of localhost.

2

Sign In to Wazuh

Two separate logins: the Indexer API (port 9200) for reading alerts, and the Manager API (port 55000) for taking action.

3

Save Credentials in n8n

Both logins are stored as secure, reusable credentials inside n8n — entered once, used everywhere they're needed.

4

Wire Credentials to the Workflow

Each workflow step uses the right credential: one to read Wazuh's alerts, one to send a response back.

5

Test Before Going Live

A trial run confirms n8n can read a real Wazuh alert and trigger an actual block — proven safe before the workflow runs unattended.

Autonomous Cloud SOC · Grafana Integration

Wiring n8n to Grafana

Nine steps to get n8n's blocked-IP alerts safely recorded into Grafana.

1

Default Login Rejected

admin/admin failed — this Grafana had a different password set.

2

Found the Real Password

Read it from Grafana's own container configuration.

3

Created a Service Account

A non-human login for n8n, given only Editor access — not full Admin.

4

Generated an Access Token

Issued once by Grafana, captured immediately — it can't be viewed again.

5

Tested the Token First

Confirmed it could actually write to Grafana before trusting it anywhere.

6

Saved as an n8n Credential

Stored securely so n8n sends it automatically with every request.

7

Linked to the Right Step

Attached to the exact workflow node that posts results to Grafana.

8

Used the Correct Address

Pointed to host.docker.internal, since Grafana is its own separate container.

Dashboard Still to Come

Debugging the Pipeline

From Failure to Success

The before/after that tells the real story — not just the finished result.

Also broken: the Wazuh API authentication token was misconfigured.

Result: repeated execution failures.

AFTER

Fix: corrected the URL and reconfigured the authentication credentials.

Verified: multiple executions completed successfully.

Reference

Key Concepts & Known Gaps

Terms used throughout this project, and an honest list of what's still unfinished.

Key Terms

Active Response — Wazuh's built-in mechanism for taking an action, like blocking an IP.
Bearer Token — a secret string sent with a request to prove it's authorized.
host.docker.internal — the address one Docker container uses to reach another on the same machine.
Indexer vs. Manager API — port 9200 searches stored alert data; port 55000 takes action.

Known Gaps

• The blocked_ip_log Data Table — existence not yet fully verified.
• The 5-minute schedule trigger is intentionally left off until a full manual run succeeds.
• The Grafana dashboard itself still needs to be built.
• Email notification credentials are not yet configured.
