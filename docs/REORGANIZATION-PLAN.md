# Repository organization guide

This guide describes the proposed folder structure. **The original files have not yet been moved.** Each move should be verified against the original contents and references before it is made.

| Proposed folder | Intended contents |
| --- | --- |
| `01-cybersecurity-fundamentals/` | Introductory security concepts and exercises |
| `02-python-and-programming/` | Python scripts, exercises, and project explanations |
| `03-linux-and-git/` | Linux commands, system setup, Git exercises |
| `04-network-security-and-soc/` | Networking, Wireshark, Wazuh, security operations |
| `05-autonomous-cloud-soc/` | Capstone architecture, configuration, tests, screenshots |
| `06-ai-and-automation/` | AI and automation exercises |
| `07-professional-development/` | Career materials and presentations safe for public sharing |
| `08-learning-journey/` | Semester reflections and progress summaries |
| `docs/` | General supporting documentation and approved screenshots |

## File handling rules

1. Keep original source files intact until their new locations are verified.
2. Avoid duplicate uploads; compare contents before removing duplicates.
3. Check for credentials, tokens, personal information, local paths, and sensitive logs before publishing.
4. Keep screenshots next to the project they demonstrate; use descriptive filenames.
5. Write each project README with: goal, tools, steps taken, evidence, challenges, and learning outcomes.
6. Separate *planned*, *attempted*, and *successfully demonstrated* work.
7. Update internal links after any folder move.
8. Keep large archives only when needed; extracted and readable project files are preferable.

## Suggested capstone documentation

- `README.md` — beginner-friendly project overview
- `architecture/` — diagrams and explanations
- `setup/` — documented configuration steps
- `rules-and-alerts/` — Wazuh rules and observed events
- `screenshots/` — evidence with captions
- `results-and-lessons.md` — observed outcomes and limitations
